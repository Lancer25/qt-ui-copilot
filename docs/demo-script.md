# 比赛演示脚本与可靠性门槛

## 演示前准备

1. 在一台有 Qt 5.9.6 与一个 Qt 6 Kit 的机器上执行 `node scripts/verify-qt-matrix.mjs --required`。
2. 为演示项目准备独立测试配置与可重放的「主窗口 → 设置 → 网络设置」路线；首次进入困难时允许人工接管，接管后保存语义路线。
3. 配置一个 OpenAI-compatible 模型端点；不要在现场依赖云端向量数据库。组件库的本地 SQLite FTS 与结构检索必须可用。
4. 执行 `node scripts/run-demo-reliability.mjs --runs 10 --fixture qt59-app`。至少 9/10 个核心运行成功才进入现场演示。

## 现场主线（约 4 分钟）

1. 导入一个真实 Qt Widgets 项目，选择 `NetworkSettings.ui`，展示已加载的 QSS/RCC 基线截图。
2. 输入需求：「复用连接测试组件，并确保英文小窗口不截断」。
3. 展示受约束的结构化操作计划、候选组件及 XML diff；批准计划。
4. 展示增强预览发现/修正布局问题，再展示项目自身 `uic` 与增量构建结果。
5. 通过保存的语义路线进入真实 EXE 的网络设置页，展示 Probe 确认、真实截图和检查证据。
6. 导出 HTML 证据报告，说明接受与回滚始终由用户确认。

## 降级策略

- UI-TARS 是可选探索器：少于 8/10 次 Probe 确认到达时，界面和讲解必须标为“实验性”，主线切换到语义路线或人工接管。
- 复杂启动状态由用户提供文字步骤、截图和测试数据；导航失败与 UI 修改失败分开报告。
- 没有可用 Qt Kit 时只能展示静态/单元功能，禁止宣称真实 Qt 5.9.6 或 Qt 6 验证通过。
- 现场保留已录制的成功运行作为网络/模型故障的备份；录制中必须清晰标注其环境与日期。
