# 组件库卡片内联预览设计

## 目标

组件详情和预览操作应与当前选中的组件保持空间关联，不再固定显示在组件列表底部。用户在长列表中选择组件后，无需滚动到底部即可查看详情、生成预览或加入当前任务。

## 交互设计

- 组件列表同一时间最多展开一个卡片。
- 单击卡片主体将其设为“正在查看”，并在该卡片内部展开详情区域。
- 单击另一张卡片时，原卡片收起，新卡片展开。
- 展开区域依次显示描述、来源与许可证、已有预览缩略图、操作按钮。
- “预览组件”沿用现有渲染流程；渲染成功后保留卡片内缩略图，并继续打开独立预览窗口。
- “加入当前任务”与“正在查看”是独立状态；已加入的卡片继续显示勾选标识。
- 预览加载状态和错误信息显示在当前展开卡片内，不在列表顶部或底部形成脱离上下文的提示。

## 组件结构

`ComponentLibraryPanel` 继续持有当前查看项、预览结果、加载状态和错误状态。`CapabilityCandidates` 增加一个可选的详情渲染入口，在对应候选项之后渲染内联详情。

每个候选项使用容器包裹“卡片主体按钮”和“内联详情”两个同级节点，禁止在按钮内部嵌套其他按钮，以保证鼠标、键盘和辅助技术交互有效。

底部固定的 `v3-component-detail` 实例删除，其视觉样式调整为卡片内部的展开面板。

## 状态与数据流

1. 用户点击卡片主体，更新 `focused`。
2. 组件列表根据 `focusedId` 在对应卡片后渲染详情。
3. 用户点击预览，当前卡片进入加载状态。
4. 渲染成功后更新当前组件的预览结果并打开独立窗口。
5. 切换查看项时，旧预览图不会错误显示到新组件；当前展示结果随查看项清理。
6. 搜索条件或来源变化导致候选项刷新时，若当前项不再存在，则收起详情并清理预览状态。

## 错误处理

- 不支持预览、未配置 Qt Kit、渲染失败等信息显示在展开卡片内。
- 错误不会阻止“加入当前任务”操作。
- 预览进行中禁用当前卡片的预览按钮，避免重复请求。

## 验证

- 测试详情只出现在当前查看卡片内部，页面底部不再生成独立详情卡。
- 测试切换候选项会移动展开详情并清除不匹配的预览。
- 测试预览按钮可点击、加载状态可见，并调用现有预览服务和独立窗口。
- 测试加入任务和当前查看两种视觉状态可以同时存在且互不覆盖。
- 运行桌面端完整测试、类型检查和便携包构建。
