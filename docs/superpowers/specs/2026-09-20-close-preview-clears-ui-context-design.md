# 关闭 UI 预览后清理文件上下文设计

## 问题

项目树打开 `.ui` 文件时，`V3Content` 同时打开预览标签并设置 `selectedFile`。关闭预览标签时，当前实现只从标签状态中删除预览，没有清除 `selectedFile`。AI 任务因此继续处于维护现有 UI 的模式，隐藏创建选项，并可能把后续请求错误路由为修改旧文件。

## 方案

- 保留现有“打开 UI 后可切换到 AI 任务继续调整”的行为。
- 当关闭的标签为持久化 UI 预览，且其 `filePath` 与当前 `selectedFile.absolutePath` 相同时，清除 `selectedFile`。
- 临时候选预览仍沿用现有 `dismissedCandidates` 逻辑；只有路径与当前文件一致时才影响文件上下文。
- 关闭设置、源码、Diff 或日志标签不改变 `selectedFile`。
- 清除后 `TaskConversationView` 的 `creationMode` 恢复为 `true`，显示组件库、创建类型和构建方式，并让下一条请求走创建流程。

## 布局结果

本次不额外调整输入框 CSS。截图中的空输出行来自错误的维护模式；恢复创建模式后第二行会重新显示完整的创建与构建配置。

## 验收

1. 打开项目中的 `.ui` 文件后，AI 任务处于维护模式。
2. 关闭该 UI 预览后，AI 任务恢复创建模式。
3. 恢复后显示“引用组件库”“完整应用”“仅界面”和构建方式。
4. 下一次提交生成 `kind: create` 请求，而不是 `kind: modify`。
5. 关闭非预览标签不清理当前 UI 文件上下文。
