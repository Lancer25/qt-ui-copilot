# Qt 动态组件库导入设计

## 目标

支持导入本地 Qt 动态组件库目录。目录可包含头文件、QSS/QRC、DLL、LIB，以及可选 JSON 清单；无清单时仍可自动发现候选并允许用户完成映射后接入项目和预览。

## 来源类型与数据模型

新增 `qt_binary` 组件来源类型，配置包含根目录、发现方式、目标 Qt Kit 与用户确认的组件映射。

每个组件映射保存：

- 组件名称、C++ 类名、基类、头文件和 include 目录。
- DLL、LIB、lib 目录及运行时依赖 DLL。
- QSS、QRC、Qt 模块、Qt 主版本、编译器 ABI、架构。
- 是否 Qt Designer 插件、默认尺寸和预览属性。
- 状态：可用、待补充、ABI 不兼容、文件缺失、探测失败。

映射只保存相对路径，所有读取与复制都验证不逃离来源根目录。

## 发现流程

1. 如果目录存在 `component-library.json`，使用其声明并验证文件。
2. 无清单时扫描 `.h/.hpp`，通过保守的词法规则识别继承 `QWidget`、`QDialog`、`QMainWindow` 的类，以及 `Q_OBJECT`、`Q_PROPERTY` 和导出宏。
3. 按同目录和同名规则关联 `.dll/.lib/.qss/.qrc`。
4. 扫描产生的候选默认是“待补充”，除非类、头文件和至少一个可用的构建二进制映射均明确。
5. 不直接在主进程加载未知 DLL。Designer 插件元数据和普通 DLL 可执行性仅由隔离探测进程检查。

## 映射交互

组件来源设置页新增“Qt 动态组件库”类型。用户选择目录、执行扫描，在映射编辑表中确认或补齐每项。未完成映射的条目可浏览，但不能加入当前 AI 任务。

同步后，组件库侧栏显示来源、组件状态、ABI 信息和预览可用性。只有可用组件可被选中并注入 AI 创建请求。

## 项目集成

使用组件时，创建或调整流程：

- 在 `.ui` 写入 `customwidgets` 声明，并使用 promoted widget 类。
- 对新 QMake 项目写入 `INCLUDEPATH`、`LIBS`、`PRE_TARGETDEPS` 和资源引用。
- 对已有项目按已有构建体系生成最小补丁；不重构项目结构。
- 将必要 DLL 复制到构建输出目录，将 QSS/QRC 作为分离资源接入。
- 未通过 ABI、Qt 主版本或架构检查的组件不写入项目。

## 预览与安全

- 探测和预览在独立子进程运行，有超时、崩溃捕获和日志。
- Designer 插件通过 Qt 插件路径加载。
- 普通组件生成临时预览工程，链接确认后的 LIB，复制 DLL，再以默认构造函数实例化。
- 初次加载未知 DLL 需要用户确认；确认记录仅限本机来源路径和内容哈希。

## 验收

1. 可导入有清单和无清单的目录。
2. 无清单头文件候选能进入映射编辑，未补齐时不可使用。
3. ABI/Qt 版本/架构不兼容明确阻止接入。
4. QMake 新项目产生正确 include、link、DLL 和资源配置。
5. 预览崩溃或超时不影响主应用。
6. 现有本地 `.ui` 组件源、MCP 来源和内置组件库不回归。
