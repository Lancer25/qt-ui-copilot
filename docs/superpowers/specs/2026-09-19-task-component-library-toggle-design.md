# AI 任务组件库引用开关设计

## 目标

在 AI 任务输入器中增加“本次任务是否引用组件库”配置，并重新组织底部控制区，避免上下文、应用方式、创建类型、构建方式和发送操作在单行中拥挤。

## 数据语义

- `TaskComposerInput` 新增 `useComponentLibrary: boolean`。
- 创建模式默认开启组件库引用，保持当前行为兼容。
- 开启时，创建请求发送 `useComponentLibrary: true`，并传递当前已选择的 `capabilityCandidates`。
- 关闭时，创建请求发送 `useComponentLibrary: false`，并传递空的 `capabilityCandidates`。
- 关闭开关不清除侧栏中已选择的组件；重新开启即可继续引用。
- 修改现有 `.ui` 文件时隐藏组件库开关，因为当前修改请求不消费组件候选。

## 组件数量

- `V3Content` 将 `selectedCapabilities.length` 传递到活动任务页。
- `ArtifactContent`、`TaskConversationView` 和 `TaskComposer` 使用 `componentCount` 只进行显示，不拥有组件选择状态。
- 有已选组件时开关显示“组件库 · N”；没有时显示“组件库”。

## 视觉结构

输入器底部拆为两个视觉层级：

1. 任务行为层：专注界面/整体模式、审批/自动应用、组件库开关。
2. 创建输出层：完整应用/仅界面、构建方式、发送/停止/排队状态。

- 两层之间使用轻量间距，不增加重边框。
- 每个分组保留独立圆角容器和明确的选中状态。
- 组件库开关使用单个 `aria-pressed` 按钮；开启显示蓝色关联图标和“引用”，关闭显示中性样式和“忽略”。
- 组件库按钮提供完整 tooltip，解释只影响本次任务。
- 发送按钮始终位于底层右侧。
- 低于 900px 时两层分别换行；低于 640px 时发送操作占据独立右对齐区域。

## 交互

- 点击组件库按钮即时切换，不提交任务。
- 选择“仅界面”时构建方式继续禁用，组件库开关不受影响。
- 运行中仍允许配置下一条排队消息是否引用组件库。
- 提交成功后保留开关状态，与其他模式选择行为一致。

## 验证

- TaskComposer 默认提交 `useComponentLibrary: true`。
- 关闭后提交 `false`，按钮 `aria-pressed=false`。
- 已选组件数量显示正确。
- V3 创建请求在开启时传递候选，关闭时清空候选。
- 修改模式不显示组件库开关。
- 1100px 与 1366px 截图中控制组不重叠、不裁剪。
- 运行桌面完整测试、类型检查和便携包构建。
