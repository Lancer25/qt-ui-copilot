# UI 图标工程与验收技能设计

## 目标

创建个人通用技能 `ui-icon-engineering`，用于新增、替换、审查或修复桌面端与 Web UI 图标。技能应主动避免字体字形造成的对齐、平台和 DPI 问题，并要求通过真实渲染验证结果。

## 触发范围

当用户提到以下任一场景时触发：

- 图标错位、模糊、不统一、不美观或大小异常。
- 图标与按钮文字、徽标、输入框或工具栏没有对齐。
- 使用 Unicode、符号字体或 Emoji 充当正式 UI 图标。
- 在不同 DPI、缩放比例、平台或字体环境中显示异常。
- 新增、替换、整理或统一项目图标系统。

纯图片创作、Logo 设计和位图素材生成不属于本技能范围。

## 核心工作流

1. 检查项目是否已有 SVG、图标组件、sprite、资源文件或设计令牌，并优先复用。
2. 定位真实根因，分别检查容器边界、SVG `viewBox`、可见路径边界、描边宽度、行高和相邻文本基线。
3. 正式 UI 图标不使用 `⊞`、`×`、箭头字符或 Emoji 等字体字形代替，除非用户明确要求文本符号。
4. 没有现成图标时使用固定 `viewBox` 的 SVG；尺寸由容器和 SVG 宽高控制，不通过字体、空格或行高塑形。
5. 先实现几何居中；如需光学校正，必须依据实际截图，并保持校正与字体、DPI 无关。
6. 添加结构性测试，确认目标控件渲染 SVG，且无旧字体字符残留。
7. 在真实应用中验证普通 DPI 与 125% DPI，并覆盖默认、悬停、选中和禁用等相关状态。

## 失败模式

技能应明确拦截以下做法：

- 只给字体字符增加 `padding`、`top` 或 `translateY` 来修复图标。
- 只验证元素盒子的 `getBoundingClientRect`，却不检查可见图形边界。
- 为同一应用引入第二套视觉风格不一致的图标库。
- 只通过单元测试或静态 CSS 检查，未查看真实渲染截图。
- 只在单一缩放比例下调整像素，导致高 DPI 再次偏移。

## 输出格式

完成图标任务后，简要报告：

1. 根因。
2. 复用或新增的图标来源。
3. 修改的容器、SVG 和状态样式。
4. 自动化测试与 DPI/窗口状态验证结果。
5. 可运行成果物或截图路径。

## 测试场景

技能提供三个评估用例：

1. React 按钮使用 Unicode 四宫格字符且视觉偏移，要求复用项目现有 SVG 组件。
2. Qt/Electron 工具栏混用 Emoji、字体符号和 SVG，要求统一图标体系与状态样式。
3. 图标在 100% DPI 正常、125% DPI 偏移，要求诊断字体依赖并做双 DPI 实测。

每个评估应检查：是否避免字体图标、是否优先复用现有资源、是否包含结构性测试、是否执行真实渲染与 DPI 验证。
