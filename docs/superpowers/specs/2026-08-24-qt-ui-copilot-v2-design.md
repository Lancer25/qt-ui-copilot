# Qt UI Copilot V2 产品与技术设计

日期：2026-08-24  
状态：已确认，待实施计划  
适用范围：Electron Renderer、设置服务与必要的 Main IPC 扩展

## 1. 目标

V2 将当前单屏原型升级为现代化、产品级的 AI 编程桌面应用，同时保留已经验证的 Qt 工作流和安全边界。

核心目标：

1. 采用现代 AI 编程产品的信息架构、墨黑紫视觉主题和多 Tab 工作方式。
2. 将模型服务、Qt Kits、构建工具、项目绑定、预览运行、导航、组件库数据源、外观和数据安全集中到独立设置页。
3. 让现有项目导入、UI 修改、审批、预览、真实运行、验证和报告能力在新界面中完整可用。
4. 新增可复用的全局多 Qt Kit 管理，并允许每个项目绑定 Kit 和运行配置。
5. 保持 Qt 5.9.6 与 Qt 6.x 的既有兼容和验证链路，不因界面重构降低稳定性。

## 2. 设计原则

- 工作流优先：用户始终能看到目标 UI、AI 当前步骤、下一步操作和验证状态。
- 渐进披露：常用操作直接可见，XML Diff、构建日志和详细诊断按需展开。
- 供应商中立：模型设置只表达 OpenAI-compatible 能力，不出现 Token Plan 等特定服务宣传或说明。
- 配置复用：Qt 环境以全局 Kit 保存，项目只保存绑定和项目特有参数。
- 真实状态：不使用静态假数据装饰页面；连接、环境和任务状态均来自实际服务。
- 安全默认：Renderer 不接触模型密钥、文件系统或进程权限。
- 可恢复：Tab、当前项目、设置分类和安全的任务视图状态可在重启后恢复。

## 3. 视觉系统

### 3.1 默认主题

采用已确认的 B1“墨黑紫 · AI 原生”主题：

- 应用背景：近黑中性色，不使用大面积纯黑。
- 面板：通过一至两级亮度差和细边框建立层级。
- 主强调色：低饱和紫色，仅用于主操作、选中状态、AI 活动状态和焦点环。
- 成功、警告、错误：分别使用克制的绿、琥珀和红色，不用强调色替代语义色。
- 默认字体：`Inter, "Microsoft YaHei UI", "Microsoft YaHei", sans-serif`。
- 圆角：6–10 px；阴影只用于浮层、菜单和模态框。
- 动画：仅用于 Tab 切换、侧栏状态、通知和执行进度，持续时间 120–200 ms。

V2 首版以深色主题为验收基线。设置页保留“外观”分类，但浅色主题不作为首版完成条件。

### 3.2 设计 Token

颜色、间距、字体、圆角、边框、阴影和动画均定义为 CSS 变量。业务组件不得直接散落硬编码颜色。交互状态至少覆盖 default、hover、active、focus-visible、disabled、loading 和 error。

## 4. 信息架构

左侧固定主导航包含：

1. AI 工作台
2. 项目与界面
3. 组件库
4. 任务历史
5. 验证报告
6. 设置

顶部为多 Tab 区域：

- AI 工作台为固定 Tab。
- `.ui` 文件、任务、报告和设置按需打开。
- 相同资源只保留一个 Tab，再次打开时聚焦现有 Tab。
- Tab 支持关闭、切换和溢出处理。
- 重启后恢复上次打开的非敏感 Tab 状态；不存在的项目资源恢复为可关闭错误态。

底部状态栏显示当前项目、Qt Kit、模型连接状态、当前任务和阻断问题数量。

## 5. 页面设计

### 5.1 AI 工作台

采用中心主画布加右侧任务栏的双栏布局：

- 顶部需求卡片：当前项目、目标 `.ui`、需求文本、参考图、组件复用入口和生成计划按钮。
- 中央运行效果：对比、快速预览、真实运行三个视图，支持前后截图同步缩放。
- 验证徽标：XML、`uic`、预览、构建、Probe、视觉评审和真实运行状态。
- 右上结构化计划：摘要、风险等级、受控操作列表和依赖。
- 右下执行时间线：节点状态、耗时、失败摘要和当前等待动作。
- 底部审批区：拒绝、批准并应用；任务运行后按状态切换为取消、人工接管、接受和回滚。
- XML Diff、构建日志、路线证据和详细检查以抽屉或子 Tab 按需打开。

### 5.2 项目与界面

- 显示最近项目、当前项目和项目导入入口。
- 以树形结构展示 `.ui`、`.qrc`、`.qss` 和相关资源。
- 双击 `.ui` 打开独立 Tab；可从此处设置为工作台目标。
- 显示项目当前 Kit、构建配置、运行目标和配置健康状态。
- 配置缺失时直接链接到“设置 / 项目绑定”。

### 5.3 组件库

- 提供搜索、标签、Qt 版本和依赖过滤。
- 使用卡片展示截图、来源 `.ui`、结构摘要、兼容性和复用成本。
- 支持选为工作台候选，并保留本地检索与可选外部数据源边界。
- 云端向量数据库只提供配置入口和 Adapter 边界，具体协议待后续对齐。

### 5.4 任务历史

- 展示任务状态、目标 UI、创建时间、耗时、失败节点和验证结果。
- 支持按项目、状态和时间筛选。
- 打开任务进入任务 Tab，显示持久化快照并允许合法的恢复操作。

### 5.5 验证报告

- 聚合前后截图、结构化计划、XML Diff、组件来源、确定性检查、视觉评审、构建、Probe 和路线证据。
- 支持打开已有报告和导出 HTML。
- 不将视觉服务不可用显示为验证通过。

### 5.6 设置

设置作为独立 Tab，左侧使用二级分类导航，右侧使用分组卡片和固定内容宽度。

分类包括：

1. 模型服务
2. Qt Kits
3. 构建工具
4. 项目绑定
5. 预览与运行
6. UI 导航
7. 组件库数据源
8. 外观
9. 数据与安全

## 6. 设置数据与行为

### 6.1 模型服务

- 配置 Base URL、模型 ID 和 API Key。
- 不展示或解释特定商业套餐名称。
- API Key 仅在 Electron Main 进程使用 `safeStorage` 加密保存。
- 分别提供文本连接、JSON 输出和图片理解检测。
- 检测结果包含耗时、HTTP 状态、能力结论和已脱敏错误信息。
- 图片理解检测使用应用内置的小型测试图片，按多模态 `image_url` 格式发送。

### 6.2 Qt Kits

每个 Kit 至少包含：

- ID、显示名称、Qt 版本和 Qt 主版本。
- 安装根目录、`bin` 目录、`uic`、`rcc`、`qmake`。
- CMake Prefix Path、编译器 ABI、架构和默认生成器。
- PreviewHost 构建/缓存状态。
- 最近检测时间和逐项健康结果。

功能包括：

- 扫描常见 Qt 安装位置。
- 手动添加、编辑、检测和删除 Kit。
- 检测版本一致性、工具存在性、ABI、CMake 可发现性和 PreviewHost 可构建性。
- 删除被项目引用的 Kit 前显示引用关系并阻止误删。

### 6.3 构建工具

- 管理 CMake 可执行文件和默认生成器。
- 展示版本检测结果。
- 为未来 qmake/自定义命令保留类型化配置，不允许 Renderer 执行任意命令。

### 6.4 项目绑定

每个项目保存：

- Qt Kit ID。
- 源码目录、构建目录、构建类型和 CMake Preset/Generator。
- 构建命令模板、目标可执行程序和启动参数。
- 环境变量白名单。
- Preview Profile、QRC、QSS、字体和插件路径。
- 语义路线或指导式导航配置。

保存前运行结构校验；涉及文件和工具的配置可执行显式“检测”，但不能仅凭路径字符串显示成功。

### 6.5 数据与安全

- 显示本地数据库和产物目录。
- 支持清理可再生成的缓存，清理前展示精确范围。
- 任务、报告或用户项目文件不属于缓存，不参与一键清理。
- 日志和错误始终脱敏 API Key、Authorization 和已知令牌格式。

## 7. Renderer 架构

将当前单体 `App.tsx` 拆分为：

```text
renderer/
├── app/
│   ├── AppShell
│   ├── navigation
│   ├── tabs
│   ├── notifications
│   └── status-bar
├── pages/
│   ├── workbench
│   ├── projects
│   ├── components
│   ├── tasks
│   ├── reports
│   └── settings
├── components/
│   ├── ui
│   ├── forms
│   └── feedback
├── state/
├── styles/
└── lib/
```

边界规则：

- 页面组合功能，基础组件不直接调用 IPC。
- Electron API 继续通过 preload 的类型化白名单暴露。
- 工作流状态以 Main 进程和 SQLite 持久化状态为权威来源。
- Tab、布局和表单草稿属于 Renderer UI 状态，与工作流状态分离。
- 不在 V2 首版为引入框架而重写已稳定的工作流后端。

## 8. Main 进程与持久化扩展

新增类型化服务和 IPC：

- Qt Kit 查询、保存、检测、删除和扫描。
- 项目绑定查询、保存和检测。
- 模型文本、JSON、视觉能力检测。
- Tab/UI 偏好持久化只保存非敏感标识和外观选项。

所有输入使用 Zod 严格校验，路径操作使用规范化绝对路径；Renderer 不能传入任意 shell 字符串。Qt Kit 与项目绑定保存到 SQLite，已有 `.qt-ui-copilot/project.json` 作为项目可移植配置继续支持，并定义明确的导入/同步优先级：用户显式保存的本地项目绑定优先，文件变化时提示重新载入，不静默覆盖。

## 9. 错误与空状态

- 页面加载失败：页面内错误卡片和重试操作。
- 短操作失败：右上角通知，并在对应字段附近给出原因。
- 长任务失败：时间线标记失败节点，提供日志和合法恢复动作。
- 模型未配置：工作台显示配置入口，不弹出阻塞式模态框。
- 项目未绑定 Kit：生成计划可用；进入 `uic`、预览或构建前明确阻断。
- 空项目、空任务、空组件库均提供一个主要下一步操作。
- 错误文案显示可操作信息，不暴露密钥、完整 Prompt 或超长服务端响应。

## 10. 可访问性与适配

- 所有交互支持键盘操作和 `focus-visible`。
- 图标按钮必须提供可访问名称和 Tooltip。
- 文本与背景对比满足 WCAG AA 的常用字号要求。
- 最小窗口宽度为 1100 px；更窄时右侧任务栏折叠为抽屉，主导航缩为图标栏。
- 125%、150% 和 200% Windows 缩放下不依赖固定像素定位。
- 列表和时间线使用局部滚动，页面不产生多层无意义滚动条。

## 11. 兼容与迁移

- 保留现有模型配置和加密 API Key。
- 首次进入 V2 时将现有项目配置识别为项目绑定候选，不修改用户项目文件。
- 现有任务 SQLite 数据继续可读。
- Qt 5.9.6 与 Qt 6.10.2 的 PreviewHost、`uic`、构建和 Probe 验证继续使用各自 Kit。
- V2 Renderer 重构不得改变结构化 UI Patch、审批、接受和回滚语义。

## 12. 测试与验收

### 12.1 自动测试

- 设计 Token 和基础组件状态测试。
- 导航、Tab 打开/去重/关闭/恢复测试。
- 工作台现有启动、审批、接管、接受和回滚测试迁移。
- 模型文本、JSON 和视觉能力检测请求测试。
- Qt Kit CRUD、扫描、健康检测和引用保护测试。
- 项目绑定校验与迁移测试。
- Electron E2E：导入项目、打开 UI、生成计划、审批、预览、真实验证、报告和设置。

### 12.2 产品验收

1. 首次启动可以从设置页完成模型、Qt Kit 和项目绑定。
2. 已安装的 Qt 5.9.6 和 Qt 6.10.2 可分别通过环境健康检测。
3. 用户可以同时打开多个 UI/任务/设置 Tab，重启后恢复。
4. 现有 Qt5 和 Qt6 E2E 工作流在 V2 界面中继续通过。
5. 模型视觉检测确实发送图片；视觉评审截图使用多模态消息。
6. 1100 px 及常用更大窗口尺寸无内容截断和页面级横向滚动。
7. 关键操作具备 loading、disabled、success 和 error 状态。
8. 应用日志、DOM 和 IPC 返回中不出现明文 API Key。

## 13. 实施边界

V2 首版包括真实可用的导航页面、统一设置、多 Qt Kit、项目绑定和现有工作流迁移。以下内容不纳入首版完成条件：

- 云端向量数据库的具体协议和账号配置。
- 浅色主题完整交付。
- 插件市场和账户系统。
- QML 支持。
- 对现有 Qt 工作流后端的大规模框架替换。

## 14. 实施顺序

1. 设计 Token、基础组件和 AppShell。
2. 多 Tab、导航、通知和状态栏。
3. 工作台迁移并保持现有测试通过。
4. 统一设置页和模型能力检测。
5. Qt Kit 管理、扫描与健康检测。
6. 项目绑定和项目页。
7. 组件库、任务历史和报告页。
8. 响应式、可访问性、E2E 和视觉打磨。

该顺序保证每个阶段都有可运行界面，并把高风险的工作流回归和环境配置放在产品打磨之前验证。
