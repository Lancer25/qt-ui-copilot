# 预览内 AI 对话调整设计

## 目标

让预览页支持沿用当前 AI 任务进行自然语言调整。用户可以针对当前预览描述修改要求，AI 基于当前 UI、预览图和对话历史生成结构化变更，刷新预览并保留 Diff、撤销和审批能力。

## 用户流程

1. 用户在预览标签中查看当前候选界面。
2. 在预览下方输入自然语言调整，例如“把顶部按钮改成蓝色并增加间距”。
3. 请求沿用当前 `taskId` 进入任务队列；任务运行时显示排队状态。
4. AI 读取当前候选 UI 源码、当前预览截图、原始需求和历史调整记录，返回结构化 UI 修改操作。
5. 系统将操作应用到候选暂存文件，执行 XML/uic 校验，并重新构建和渲染预览。
6. 预览页展示新结果和 Diff；用户可继续对话、撤销本次调整、放弃候选或审批保存。

## 模式边界

- 创建模式：调整当前完整应用候选中的 UI 文件，工程文件和构建配置保持不变。
- 修改模式：调整当前已打开的 `.ui` 文件，继续使用现有 RevisionService 的安全提交规则。
- 所有调整在候选或 revision 暂存区完成，审批前不直接覆盖项目文件。

## 对话与上下文

- 复用当前任务 `taskId` 和 TaskStreamStore 的队列机制。
- 新增调整请求类型，包含 `taskId`、目标 UI 路径、当前 UI 内容、用户描述、上下文模式和可选预览图。
- 服务端保存每次调整的摘要、操作列表、输入 hash 和输出 hash，供后续对话引用。
- 预览图仅作为模型上下文传递，不写入项目源文件；路径和附件大小继续使用现有边界。

## AI 输出与安全校验

- AI 只能返回已注册的结构化 UI 操作，不允许返回任意 XML、C++、脚本或文件路径。
- 操作应用后依次执行 XML 解析、语义校验和 `uic` 校验；任一失败则丢弃本次调整并保留上一版本。
- 对创建模式候选，更新候选的 `source`、hash、预览图和 Diff，但不改变工程文件清单中的非 UI 文件。
- 对模型超时、格式错误或不支持的操作，显示可复制错误并允许重试，不自动重写整个界面。

## 预览与任务状态

- 调整过程按“排队 → AI 分析 → 应用变更 → uic 校验 → 构建 → 预览”流式显示。
- 当前预览保持可见；新预览准备完成前不清空旧截图。
- 构建或预览失败时保留上一张有效预览，并显示失败阶段、日志和“重试调整/恢复上一版本”操作。
- 取消任务会终止当前调整和后续构建，不产生半完成候选。

## 交互与撤销

- 预览页提供调整输入框、发送/停止按钮、处理中状态和最近调整摘要。
- 每次调整生成独立 Diff，可单次撤销；连续调整仍保留在同一任务会话中。
- “放弃”删除整个候选；“审批并保存”提交当前完整候选；修改模式沿用原有审批入口。

## 验证标准

- 预览页发送调整后复用原 `taskId`，运行中的任务会正确排队。
- AI 返回合法操作时，UI 源码、hash、预览和 Diff 同步更新。
- 非法操作、uic 失败、构建失败和预览失败均不会破坏上一有效版本。
- 创建模式和修改模式分别覆盖成功、失败、取消、重试和撤销测试。
