# 组件选中自动预览设计

## 目标

用户选中可预览组件后，应用自动在当前卡片内生成预览；渲染成功不得自动打开独立窗口。用户只有在点击预览图或放大入口时才打开大图。

## 交互规则

- 首次选中可预览组件时立即开始渲染，无需再点击“生成组件预览”。
- 渲染过程中在当前卡片内显示稳定的加载状态。
- 渲染成功后仅更新卡片内截图，不调用 `preview.openWindow`。
- 点击卡片内截图时调用 `preview.openWindow`，以独立窗口放大显示。
- 点击“重新生成预览”时重新渲染并更新缓存，但仍不自动打开独立窗口。
- 不可预览组件继续显示不可用说明，不发起请求。
- 渲染失败继续显示原位错误和重试入口。

## 会话缓存

- 预览结果按 `capabilityId` 缓存在 `ComponentLibraryPanel` 当前会话中。
- 切换回已成功预览的组件时直接显示缓存，不重复渲染。
- 主动重新生成会覆盖该组件缓存。
- 搜索结果刷新不会清除仍然存在组件的缓存。
- 组件来源、工作区或 Qt Profile 变化时清空缓存，避免展示与当前环境不匹配的截图。

## 并发与错误

- 每次渲染继续使用递增请求序列。
- 切换组件使旧请求失效；迟到结果不得写入缓存、显示错误或打开窗口。
- 预览错误只属于当前组件；切换组件时清除当前错误。
- 自动渲染与 React StrictMode 不得产生重复请求。选中处理函数在确认没有缓存后直接发起一次请求，不使用重复触发的挂载副作用。

## 组件边界

- `ComponentPreviewSurface` 保持纯展示组件：成功截图点击触发 `onOpen`，刷新或重试触发 `onGenerate`。
- `ComponentLibraryPanel` 负责自动渲染、按组件缓存、请求序列和独立窗口调用。
- 后端预览协议不变。

## 验证

- 测试选中可预览组件会自动调用一次预览服务。
- 测试成功后不会自动调用 `openWindow`。
- 测试点击截图才调用 `openWindow`，并且不会再次渲染。
- 测试切换后再次选中使用缓存。
- 测试重新生成覆盖缓存且不打开窗口。
- 测试环境变化清空缓存并重新渲染。
- 保留旧请求防串项、失败重试和不可预览测试。
- 运行桌面完整测试、类型检查、格式检查和便携包构建。
