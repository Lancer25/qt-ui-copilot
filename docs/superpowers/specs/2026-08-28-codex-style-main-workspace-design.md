# Qt UI Copilot Codex 式主工作区设计

## 1. 目标

将现有三栏 IDE 工作台重构为以 AI 任务对话为中心的 Codex 式工作区。项目文件树保留在左侧，中央区域承载 AI 对话和所有成果物 Tab；Qt 预览、源码、Diff 与日志在需要时打开，不再常驻挤压对话空间。

本阶段覆盖主界面信息架构、流式任务消息、内部成果 Tab、候选预览与审批。独立系统预览窗口不纳入本阶段。

## 2. 主界面结构

主窗口由四层组成：

1. 顶部标题栏：应用名称、当前工作区名称和无边框窗口控制按钮。
2. 左侧活动栏：文件、任务、搜索、组件、设置入口。
3. 左侧内容栏：默认显示项目文件树；切换“任务”后显示 AI 任务历史。
4. 中央 Tab 工作区：承载 AI 任务、Qt 预览、UI XML、Diff 和 Output。

删除右侧常驻 `AI ASSISTANT` 面板。AI 对话成为中央默认 Tab，输入框固定在任务 Tab 底部，支持文本、图片和 Qt 文件拖入。

中央 Tab 类型：

- `task`：AI 对话与流式执行。
- `preview`：实际 Qt PreviewHost 渲染。
- `source`：只读或后续可编辑的 `.ui` XML。
- `diff`：候选与正式文件差异及审批动作。
- `output`：技术日志与诊断。

同一 `.ui` 文件的同类型 Tab 只能存在一个；重复打开时激活已有 Tab。

## 3. AI 对话与流式状态

用户需求显示为普通对话消息。AI 输出使用增量消息流，文本、执行状态和成果物按照真实事件顺序追加。

执行状态使用紧凑状态行：

- 等待：低对比度文字。
- 执行中：动态圆点、当前动作和已耗时。
- 完成：绿色对勾和简短结果。
- 警告：黄色提示，不阻止基础候选保存。
- 失败：红色摘要，可展开技术详情。
- 取消：灰色终止状态，保留已经生成的候选。

默认状态文案面向普通用户，例如“正在读取参考图片”“基础 UI 已通过 uic”“正在生成实际预览”。请求体、堆栈和 PreviewHost 日志放入“查看详情”。

用户在任务执行期间仍可输入。新消息进入当前任务队列，并在本轮安全边界完成后继续执行。输入区同时提供“停止”动作，停止请求通过已有 taskId 取消 Main 进程任务。

429、超时和服务异常以消息内警告呈现。“继续当前任务”复用 taskId、已完成事件、基础候选和预览状态；仅当模型尚未返回任何可持久化结果时重新发送模型请求。

## 4. 成果物与审批

生成基础 `.ui` 后，在 AI 消息流中插入成果卡片。卡片显示文件名、uic 状态、预览状态和三个主要动作：

- 打开预览；
- 查看 Diff；
- 审批并保存。

生成候选后自动打开临时 `preview` Tab。该 Tab 带“待审批”标记，使用完整中央画布展示实际 Qt 渲染结果。

预览 Tab 工具栏包含快速预览、增强预览、刷新、适应窗口和 100% 缩放。底部审批条包含放弃、查看 Diff、审批并保存。

审批成功后：

1. 候选文件写入目标目录。
2. 临时预览 Tab 转为正式文件 Tab。
3. 项目文件树自动刷新并展开到新文件。
4. AI 任务消息追加“已保存”结果。

PreviewHost 失败时，基础候选仍可在通过 uic 后保存。预览 Tab 显示可操作诊断，并提供查看 XML、重试预览和保存基础版本。

## 5. 状态与组件边界

### WorkspaceShell

负责标题栏、活动栏、左侧内容栏和中央 Tab 容器。它不解释 AI 事件，也不直接调用 PreviewHost。

### TaskConversationView

负责消息列表、流式状态行、成果卡片、附件和输入区。输入为 taskId 与规范化事件序列，输出为继续、停止、打开成果物和审批意图。

### ArtifactTabManager

负责成果 Tab 的唯一性、激活、关闭、临时候选到正式文件的转换，以及任务与文件的关联。

### UiPreviewTab

负责 PreviewHost 请求、快速/增强模式、刷新、缩放、降级诊断和审批条。它不管理 AI 对话内容。

### TaskStreamStore

以 taskId 为键保存事件序列、消息、候选、预览状态和待处理输入。根据单调 sequence 去重并拒绝旧事件回退状态。

## 6. 数据流

```text
Main 进程任务事件
  → IPC 流式事件
  → TaskStreamStore 去重与归并
  → TaskConversationView 渲染文本和状态行
  → 成果卡片创建 Artifact Tab
  → UiPreviewTab 调用 PreviewHost
  → 审批结果回写文件并刷新 Explorer
```

Main 进程是任务事实来源；Renderer 只负责展示和用户意图。刷新或切换任务后，通过持久化任务快照恢复消息、候选和预览状态。

## 7. 错误处理

- 模型无响应：显示超时消息和继续按钮，保留已完成状态。
- 模型限流或额度不足：区分 429 限流与额度错误，不自动清空任务。
- 蓝图兼容降级：记录警告，继续生成可用基础 UI。
- uic 失败：阻止审批保存，提供 XML 与诊断详情。
- PreviewHost 失败：不阻止保存已通过 uic 的基础版本。
- 文件保存冲突：保留候选，要求用户改名或覆盖确认。
- 文件树刷新失败：显示非阻塞提示，并保留手动刷新入口。

## 8. 视觉原则

- 中性灰深色主题继续沿用。
- AI 任务内容最大宽度保持适合阅读，输入区固定底部。
- 状态行使用轻量图标和单行摘要，避免大面积步骤卡片。
- 技术详情默认折叠。
- 预览使用完整画布，审批操作固定在预览底部。
- 动画仅用于当前执行状态、流式光标和 Tab 加载，不使用持续大面积闪烁。

## 9. 验证标准

- 启动后默认进入 AI 任务 Tab，旧右侧 AI 面板不再出现。
- 左侧文件树与任务历史可以切换。
- 流式事件按 sequence 渲染，重复事件和旧事件不会导致状态回退。
- 执行期间允许输入排队并允许停止。
- 失败后继续使用原 taskId 和已有候选。
- 同一 `.ui` 的预览、源码和 Diff Tab 不重复创建。
- 生成候选后自动打开待审批预览 Tab。
- 审批后候选转为正式文件并自动刷新文件树。
- Qt 5.9.6 与 Qt 6 的快速/增强预览回归通过。
- PreviewHost 失败时仍可保存通过 uic 的基础版本。
- 键盘焦点、Tab 语义、aria-label 和错误状态满足现有可访问性测试约束。
